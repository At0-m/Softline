# Junior · GLM · витрина и аналитика

**Мандат.** Покупатель должен за один экран понять, какой товар подходит и почему. Менеджер должен из проблемного запроса открыть фактическую выдачу. Ты владеешь UI, клиентом поискового API, отправкой кликов и проверками пользовательских состояний. Прочитай [контракт](../docs/contract.md) и открой [пример ответа](../fixtures/search-response.json).

### J1. Сделай UI параллельно с импортом

1. На фикстуре подготовь одну строку поиска, область основной выдачи, отдельно подписанные альтернативы и дополнения. На карточке нужны название, тип, цена при наличии, ссылка на магазин и короткое основание. Категория ведёт на страницу подборки. Счётчик считает товары, исключая заголовки.
2. Покажи четыре состояния: загрузка, найден целевой товар/категория, прямого совпадения нет, произошёл технический сбой. При shortfall показывай реальное число карточек. При отсутствующей цене используй фактическую пометку из данных либо «Цена не указана».
3. У дополнения есть ссылка на описание вендора и указано, к какому продукту относится рекомендация. Подпись «Совместимые решения» допустима при доказанной совместимости. Для пользователя понятно, если меняется платформа, редакция или формат лицензии.
4. Отдай Senior путь или скрин демонстрации фикстуры и список недостающих полей, сохрани пример отдельно от боевой сборки.

### J2. Подключи реальный сервис

| Сценарий | Ожидание в UI |
|---|---|
| «сервер» → «антивирус для сервера» | Видна смена категорий. Медленный ответ на первый запрос не затирает второй |
| «кибер бэкап» | Заголовок открывает целевую подборку, под ним реальные карточки с индивидуальными ссылками |
| Нашлась одна точная позиция | Прямая позиция первая. Альтернативы и дополнения явно подписаны, причины различимы |
| Уточнение или ошибка модели | Предыдущие актуальные фильтры видны, локальная выдача остаётся рабочей |
| Клик по карточке | Открывается правильная страница Softline. Отправляется click с request_id, item_id, позицией и event_id. При повторной доставке ID сохраняется |

**Экран менеджера.** Покажи период, источник, число запросов, количество выдач без прямого результата и нарушений правила 4+. В списке — исходная фраза, наблюдаемая причина, пример выдачи и что проверить. Для неизвестной причины поставь «требует разбора». Пустой период имеет собственное понятное состояние. Отдели контрольный прогон от живого трафика, не выводи конверсию в заказы из одних кликов.

**Бонус.** Подсказки по префиксу бери после подключения реальных данных и кликов. При быстром вводе отменяй старый запрос или игнорируй устаревший ответ, давай выбрать подсказку с клавиатуры.

**Передача Sol.** Приложи URL поиска и аналитики, commit и точные действия для проверки одного прямого попадания, дополнения, клика, пустого периода и shortfall. Отметь, что проверено на реальном сервере. Перед записью на демостенде не должно оставаться доменов .invalid из фикстуры.
