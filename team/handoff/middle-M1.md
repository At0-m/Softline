## 3. Цели XLSX → сопоставление с каталогом

**Фактическая структура XLSX:** 1 лист `Sheet1`, колонки `A` «Пример запроса»,
`B` «Целевой ответ (первый товар в выдаче или категория)» (с пробелом на конце).
Непустых эталонов: **10** (строки 2–11), пропущенных строк 0.

**Главный вывод:** прямых совпадений по URL — **0 из 10**. Витрина использует
человекочитаемые слаги (`/kripto-pro/cryptopro-csp/`), фид — hash-id слаги
(`/kripto-pro/-25218/`, `/adobe/65272676ba01a12-504/`). Все 136 040 URL товаров
без query string. Сопоставление целей возможно только через название/вендора
или страницу витрины.

| Тип цели | Число | Совпадение |
|---|---|---|
| Товар (`/<vendor-slug>/<product-slug>/`) | 8 | 0 exact, 0 path, **8 heuristic** (токены названия после транслитерации) |
| Категория с фильтром (`?filter[category][]=1033`) | 1 | categoryId 1033 найден в справочнике фида → «Программное обеспечение для резервного копирования». URL категорий в фиде отсутствуют. |
| Страница направления (`/webinar/`) | 1 | Сегмент `webinar` встречается в 3 URL товаров фида, отдельной карточки нет |

Значимые query-параметры сохранены: `filter%5Bcategory%5D%5B%5D=1033`
декодирован как `filter[category][]=1033`, id категории резолвится по снимку.

### Два показательных несовпадения heuristic-этапа

1. **«365» → `…/microsoft/microsoft-365-for-family/`** — эвристика вернула
   Dynamics 365 (id 103886). В фиде есть «Microsoft 365 для бизнеса» и «для
   предприятий» (cat 1145), а продукта семейства *для дома/family* по
   русскому названию не найдено. Причина: слаг на английском, название в фиде
   на русском + вероятно отсутствие самого товара — **причина пока неизвестна**,
   нужна сверка с витриной.
2. **«astra linux» → `…/astralinux/astra-linux-special-edition/`** — эвристика
   вернула «Сертификат техподдержки на ОС «Astra Linux Special Edition»»
   (id 482091) вместо самой ОС. Причина известна: токены названия совпадают,
   но тип предложения другой (сертификат/услуга vs лицензия на ПО). M2 нужен
   признак «тип предложения» и ранжирование перед эвристикой.
   Дополнительно: standalone-ОС в фиде ищется по «Astra Linux Special Edition»
   среди карточек вендора `astralinux` (1711 карточек), но первые кандидаты —
   комплекты «Сканер-ВС + ОС».

## 5. Что передаю дальше и риски

* **Senior:** снимок готов для индекса M2; дешёвый baseline — точное совпадение
  по `name`/`vendor` + транслитерация (см. `match_targets.py`, skeleton-функция).
  URL витрины из XLSX не резолвятся напрямую — первичный маршрут цели должен
  идти через название+вендора, а hash-slug фида использовать как канонический
  `item.url`. Примеры реальных ID: 410137, 473582, 486957, 25266, 482091, 103886.
* **Junior:** данные получит через контрактный интерфейс Senior; для макета
  карточек реальные значения полей выше.
* **Sol:** эталон 10 запросов покрывается эвристикой в 8/8 товаров + 1 категория
  + 1 страница направления; два кейса (365, astra) рекомендую держать как
  обязательные негативные проверки ранжирования.
* **Риски:** 59 % нулевых цен; английские слаги против русских названий
  (нужны алиасы, Junior UI может наткнуться при `365`); «сертификат/услуга»
  не отделены от лицензий; `group_id` отсутствует у 8 % карточек — семейства
  собирать аккуратно; страницы категорий в фиде нет — цели категорий берём из
  XLSX и адресов витрины, источник документирую в M2.
* Команда запуска и smoke-тесты: `tools/middle/README.md`. Полный фид, XLSX и
  выгрузки в Git не попадают (`.gitignore`), отчёты прогонов — `data/out/`.
