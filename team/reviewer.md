# Reviewer · Sol · независимая проверка

**Мандат.** Проверить пользу и воспроизводимость, обнаружить регрессии и дать Senior обоснованный release verdict. Владеешь разметкой, сравнением, сценариями отказа и отчётом. Изменения продукта возвращай владельцу модуля. Начни с [приёмки](../docs/acceptance.md), [контракта](../docs/contract.md) и [сценария демо](../docs/release.md).

### R1. Подготовь контроль до интеграции

- Зафиксируй список непустых эталонов из XLSX с исходной строкой и канонической целью. Пометь product/category. Для shop URL сохрани фильтры категории. Пропуски в фиде выдели отдельной причиной.
- Сделай небольшой независимый набор: переформулировки, опечатки, сленг, пары со сменой объекта покупки, артикул и запрос без прямого результата. Для каждого сохрани ожидаемый тип и проверяемые признаки. Семейства перефразировок держи вместе при разбиении. До финального прогона разработчикам достаточно знать классы проверок.
- Подготовь процедуру оценки четырёх позиций. Для альтернативы проверь раскрытое отличие, для дополнения — совместимость и ссылку. Цели из известного XLSX могут использоваться при разработке, поэтому их результат отчитай отдельно от отложенных примеров.
- Сверь эталоны с действительным ассортиментом. Для невозможного эталона зафиксируй причину, долю покрытия и его влияние на общий результат. Отсутствие нужного товара не исправляется подменой ожидаемого ответа.

### R2. Гони через обычные точки входа

Сними baseline и финальную выдачу на одном снимке. Запиши commit, настройки, время, размер набора, состояние кеша и маршруты. Сравни Top‑1 по URL, число релевантных карточек из четырёх, покрытие 4+, ссылки и нарушения ограничений. Покажи хотя бы один выигрыш, один оставшийся промах и регрессии, если они есть. Измерь fallback при недоступной модели, повторы событий, сохранение значимых URL-фильтров и корректность переходов в UI.

**Три обязательных контрпримера.** Похожее серверное ПО по запросу на оборудование. Соседняя версия продукта с неподтверждённой совместимостью. Четыре варианта объёма лицензии с одной канонической карточкой. Каждый из трёх может дать красивую, но ложноположительную выдачу.

### Решение о выпуске

| Уровень | Как поступить |
|---|---|
| Blocker | Пример — не работает поиск со стенда, выдан вымышленный товар/источник, ошибочно заявлена совместимость или acceptance-цифры нельзя повторить. Немедленно сообщи Senior и владельцу. |
| Major | Пример — валидные кандидаты есть, а ключевой запрос показывает меньше четырёх товаров, неверный первый URL либо клики дублируются. Перед повторным прогоном укажи затронутый критерий. Если затронут основной сценарий сдачи — статус Blocker. |
| Minor | Визуальное или диагностическое неудобство при сохранённом пользовательском результате. Передай с примером и влиянием, оставь Senior выбор очередности. |

Формат заключения: GO или HOLD, ревизия, snapshot, что проверено, метрики с числителями и знаменателями, нерешённые блокеры, непроверенная область, ссылки на artefacts прогона. GO означает техническую готовность по проверенной области. Решение об отправке принимает участник.
