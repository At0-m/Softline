# Handoff Junior → Senior · J1

**ID задачи:** J1 — UI поиска на фикстуре
**Ревизия:** см. SHA ниже (ветка `feat/j1-search-ui`)
**Вход:** `docs/contract.md` v1, `fixtures/search-response.json` (не изменён)
**Дата:** 2026-11-27

## Как повторить

```
python3 client/dev_server.py      # Python 3.12 stdlib, зависимостей нет
# открыть http://localhost:5173/
```

Демо-запросы: `сервер` (основная фикстура), `мало` (shortfall),
`нет совпадений` (0 direct), `дополнение` (complement + альтернатива),
`ошибка сервера` (HTTP 500 → экран сбоя). Пустой запрос → 400 с сообщением.

## Что получилось

- Четыре состояния UI: загрузка (спиннер, искусственная задержка заглушки),
  результат, «прямого совпадения нет» (успешный ответ, пометка + альтернативы),
  технический сбой (500 + повтор поиска).
- Карточка: название (ссылка в магазин), бейдж relation, категория-ссылка на
  подборку, цена или «Цена не указана» (нуль пропуском не считается), основание
  `why`. У complement: «Дополнение к …» (резолв base_id) + ссылка на источник
  вендора с датой проверки и claim. Секции подписаны: Прямые совпадения /
  Альтернативы / Дополнения.
- Счётчик считает только карточки, заголовки секций не входят. При shortfall
  показывается фактическое число карточек и reason.
- Замена источника данных: одна константа `SEARCH_API_BASE` в
  `client/api-config.js`; `cards.js`/`app.js` знают только схему контракта.
  POST /search уже идёт через клиент (`client/api.js`), заглушка лишь отдаёт
  договорные JSON.
- Гард устаревших ответов по порядковому номеру запроса (быстрый повторный
  ввод не затирается медленным старым ответом).
- Тестовые примеры shortfall / no-direct / complement:
  `fixtures/ui-cases/*.json` + README с маркировкой fixture-only. Исходная
  фикстура `fixtures/search-response.json` не изменена.

## Что проверено (мной, локально)

- Прогон всех веток POST /search: 200/200/200/200/500/400, тела соответствуют
  фикстурам.
- Контрактная валидация фикстур: обязательные поля карточек, base_id+evidence
  у complement, суммы counts = items, инвариант shortfall↔distinct<4.
- Логика `cards.js` исполнена на реальном JSON фикстуры с DOM-заглушкой:
  счётчик без заголовков, резолв base_id, цена/пропуск цены, секция альтернатив
  при 0 direct. Синтаксис браузерного JS в окружении без Node/V8 не проверялся
  автоматически — вычитан вручную; проверить в браузере на стенде.

## Что осталось проверить на реальном API (J2)

- Живой POST /search: смена категории «сервер» → «антивирус для сервера»,
  реальные карточки и индивидуальные ссылки, целевая подборка под заголовком.
- Поведение при route=fallback с reason и медленном первом запросе при
  быстром повторном вводе (гард стоит, нужно на реальных задержках).
- Отправка событий POST /events (click с request_id, item_id, позицией,
  event_id; идемпотентность повтора) — в J1 не реализована, клики просто
  открывают магазин в новой вкладке.
- Экран менеджера аналитики (GET /analytics) — не начат, J2.
- Отсутствующие в фикстуре поля для реальных карточек: изображение товара,
  вендор, доступность на складе, фактическая цена в рублях, канонические URL
  подборок категорий.

## Ограничения

- `.invalid`-домены и синтетические карточки — до демостенда заменить нельзя,
  UI их не distinguishes; перед стендом убрать демо-чипы из `index.html`.
- Node.js в окружении нет, поэтому заглушка на Python; клиентский код от
  серверного рантайма не зависит.
