# Middle · GLM · каталог и retrieval

**Мандат.** Превратить XML и таблицу целей в воспроизводимый поиск, дать Senior дешёвый baseline и пригодных для повторного ранжирования кандидатов. Владеешь загрузкой, сопоставлением сущностей, индексами и поиском по полям. Прочитай [контракт](../docs/contract.md) и [описание данных](../docs/product.md).

### M1. Профиль фида до выбора поискового движка

1. Проверь формат по байтам, обработай подходящее сжатие и потоковый XML. Зафиксируй дату/хеш снимка, фактические теги, число прочитанных записей и категорий. На срезе явно укажи критерий отбора.
2. Покажи по одной сырой и нормализованной записи оборудования и ПО. Сопоставь ID/артикул, название, бренд, категорию и её родителей, URL товара, цену и валюту, наличие, семейство, атрибуты и версии. Неизвестное сохраняй пустым. Вычисли долю заполнения по важным полям.
3. Сверь URL целей XLSX с каталогом. Раздели товар, категорию и страницу вендора с фильтром. Не выбрасывай query string, меняющий выборку. Если фид не содержит URL категорий, используй подтверждённые адреса витрины и документируй происхождение.
4. При импорте повторно обновляй по стабильному ID. Новую версию переключай только после успешной сборки. Повреждённый повторный импорт должен оставить предыдущий индекс доступным. При первом неуспешном импорте верни явный статус отсутствия индекса.
5. Передай Senior snapshot, примеры реальных ID, название отсутствующих полей и рабочий локальный вызов. Junior получит данные через согласованный интерфейс.

### M2. Поиск и эксперимент

| Канал | Поведение |
|---|---|
| Baseline | Зафиксированное простое текстовое совпадение на том же фиде. Укажи поля и порядок. Это воспроизводимый прокси штатного поиска, если у команды нет реальной выдачи магазина. |
| Поиск MVP | Точный SKU и название, алиасы, категория, бренд. Описание имеет меньший вес. Нормализация учитывает регистр, смешение алфавитов, опечатки, сленг и формы слов, сохраняя цифры, модель и версию. |
| Семантический канал | Подключай при готовом локальном baseline. Смешай списки кандидатов и устрани дубли по ID/семейству. Сравни с лексическим маршрутом на том же снимке, отметь время построения. При ограничении ресурсов отдай интеграцию рабочего лексического канала раньше. |

Обеспечь фильтрацию по реальным категориям и полям. Для пары «сервер / антивирус для сервера» верни Senior тип кандидата и признаки совпадения. Пусть классификатор может различить продаваемый объект и объект применения. Для SKU приоритет имеет точное совпадение. Фильтры ОС и срока применяй к тем вариантам лицензий, для которых они подтверждены. Повтор описания и множество вариантов одной карточки не должны занимать всю четвёрку.

**Приёмка твоего модуля.** Повторная загрузка стабильна, запрос по известному ID детерминирован, версии и значимые URL-фильтры сохранены, поиск не ломается на опечатке, отсутствующем атрибуте или пустой цене. Покажи Senior строки с корректным попаданием и с промахом. Sol получает одноразовую команду baseline, число индексированных объектов, перечень исключённых классов и ревизию настроек. Если алиас добавлен по известному эталону партнёра, раскрывай его как курируемое правило.
