# Контракт v1 · Senior, Middle, Junior и Sol

Имена ниже — рабочее соглашение для нового проекта. Если проект уже имеет API, Senior документирует однозначное соответствие и сохраняет существующие точки входа. [Пример ответа для UI](../fixtures/search-response.json) содержит четыре синтетические карточки. Домены .invalid специально зарезервированы для фикстуры.

## Поиск и отображение

**POST /search.** Обязательное поле query содержит непустую строку. Опциональные session_id и filters несут контекст и явные ограничения. Пустая строка возвращает 400 с сообщением для UI. Результат с нулём прямых совпадений — успешный ответ поиска. Прерванный запрос при быстром повторном вводе не должен перезаписывать новую выдачу.

| Поле ответа | Значение |
|---|---|
| request_id, index_version | Идентификатор попытки и снимка каталога |
| route | local, agent или fallback. При fallback добавить reason |
| intent | Искомый тип товара и требуемые атрибуты. Неопределённость допустима |
| target | type — product или category, url — канонический адрес, label — человекочитаемое название. null, если уверенной первой цели нет |
| items | Упорядоченный массив карточек. Сначала прямые совпадения, затем явно подписанные альтернативы и дополнения. Первая прямая карточка соответствует target типа product |
| counts | direct, alternative, complement и distinct. Считаются по финальной выдаче |
| shortfall | true, когда уникальных обоснованных карточек меньше четырёх. reason объясняет почему |
| latency_ms | Серверная задержка в миллисекундах |

**Карточка.** Обязательны id, title, url, category, relation, why. Значения relation — direct, alternative, complement. Цена — объект amount/currency или null. Нулём пропуск не заменяется. Для дополнения обязательны base_id и evidence с source_url, checked_at, claim. Точные версии входят в claim или отдельные поля. Альтернатива указывает отличие и явно сообщает об ослабленном условии. Ссылки на покупку ведут в магазин. Внешняя ссылка открывает основание рекомендации.

**Инвариант четырёх.** По умолчанию учитываются различные продукты во всей выдаче, метрика прямых попаданий считается отдельно. Категория и баннер дают ноль карточек. При канонически одинаковой странице товара и различиях только в объёме лицензий показывать семейство с вариантами. Иные редакции с существенными отличиями допускаются при отдельной карточке с ясным названием. Если прямых результатов нет, пользователь видит пометку и осмысленные альтернативы. Если обоснованных товаров суммарно меньше четырёх, выставить shortfall и включить запрос в отчёт нарушений. Уточнение партнёра имеет приоритет.

## Внутренние инструменты runtime

| Инструмент | Вход | Выход и ограничения |
|---|---|---|
| Поиск кандидатов | text, допустимые category/vendor/attributes, лимит | Существующие ID, признаки точного совпадения и категория, версия индекса |
| Чтение карточек | ID кандидатов, index_version | Только данные снимка. Неизвестные ID отсеиваются с причиной |
| Связи продукта | base_id, версия/редакция при наличии | Связанные ID, тип связи и подтверждение. Совместимость действует только в области источника |

LLM выбирает действие в рамках известного списка и возвращает поля заданной формы. Senior валидирует типы, фильтры и ID, затем сам читает карточки. Один дополнительный retrieval и один вызов LLM на запрос — бюджет MVP. Текст описания, модель и внешняя страница не могут подменить URL или цену товара. Клиентская сессия хранит последний тип и явные условия. Новая самостоятельная фраза начинает новый intent, уточнение изменяет указанные поля.

## События и отчёт

**POST /events.** Клиент передаёт event_id, request_id, type=click, item_id, position (от 1), occurred_at. Сервер проверяет соответствие item_id ранее показанной выдаче. Уникальный event_id делает повтор успешной доставкой без второго клика. Выдачу type=impression фиксирует сам сервер один раз при формировании ответа. origin — live, eval или fixture. Оценочный прогон помечает доверенный серверный контекст. Клик не задерживает переход покупателя.

**GET /analytics.** Фильтры — период и origin. Элементы отчёта — query_group, count, issue_type, example_request_id и фактические карточки/ссылка на разбор. Отдельно total_requests, no_direct, shortfall и fallback_count. Пустой период возвращает пустой список и нулевые количества. Ошибка категории подтверждается ручной разметкой или сравнением с эталоном. Отсутствие покупки или клика само по себе такой диагноз не устанавливает.

**GET /suggest** с префиксом — бонус после P0. Вернуть небольшой список подписанных товаров или категорий из локального индекса. UI отменяет устаревшие запросы. Клиент начинает отправку после короткой паузы в наборе, LLM в этом маршруте не используется.
