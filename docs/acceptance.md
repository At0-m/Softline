# Приёмка и измерения

Владелец — Sol. Для каждого прогона сохранить время, commit, снимок фида, конфигурацию retrieval, модель, состояние кеша, число запусков и источник набора. В протоколе одна строка на запрос. Минимальные поля — ID, текст, ожидаемая цель, четыре возвращённых ID и их роли, первая фактическая цель, причина промаха, маршрут и задержка.

| ID | Действие | Наблюдаемая проверка |
|---|---|---|
| A01 | Ввести известный артикул и продукт из XLSX | Ожидаемая каноническая карточка первая. Повтор на том же снимке сохраняет цель |
| A02 | Найти «мтс» и «кибер бэкап» | Первый переход ведёт на целевую страницу из XLSX, значимые фильтры сохранены. На экран выводятся товары |
| A03 | Сравнить «сервер», «антивирус для сервера» | Тип объекта покупки меняется. Проверка по категориям и карточкам выявляет ложное совпадение по описанию |
| A04 | Повторить известные намерения с опечаткой и жаргоном | Фиксируются Top‑1 и состав первой четвёрки на отложенных вариантах |
| A05 | Открыть дополнение к проверенной версии основного продукта | Товар и источник существуют, версии и смысл рекомендации совпадают. На соседней неподтверждённой версии утверждение не повторяется |
| A06 | Выбрать запрос с малым числом прямых кандидатов | Альтернативы подписаны. Дубли канонической карточки исключены. Реальный shortfall виден в UI и аналитике |
| A07 | Отключить LLM, дать сложный запрос | Ответ завершается локальной выдачей с route=fallback. Есть причина и измеренное время. Точный запрос по-прежнему локальный |
| A08 | Отправить один click дважды с тем же event_id | В аналитике один клик, поиск и переход работают. Контрольные запросы можно исключить из live |
| A09 | Ввести два запроса быстро, искусственно задержать первый | UI сохраняет результаты последней фразы. Запрос без совпадений имеет понятный результат |
| A10 | Перезапустить сервис и повторно импортировать снимок | Товар не дублируется. Сбой переимпорта сохраняет доступный предыдущий снимок |
| A11 | Открыть стенд без авторизации с чистой сессией | Доступны поиск и переход в магазин. Метрики и задокументированный пример воспроизводятся, UI не содержит элементов фикстуры |

### Как считать

- **Top‑1** — число совпадений первой цели с эталонным URL / число заданных эталонов. Добавить покрытие целей фидом и отдельно условный Top‑1 для достижимых целей. Результаты известного и независимого наборов показать раздельно.
- **Релевантность первой четвёрки** — число вручную подтверждённых карточек в заявленной роли / (4 × число проверенных запросов). Пропуск равен нулю. Отдельно дать долю прямых соответствий и число нарушений жёстких условий. Дополнение не может засчитываться как прямой ответ.
- **Покрытие 4+** — число запросов с минимум четырьмя разными реальными продуктами / все запросы прогона. Дополнительно — число запросов без прямого результата. Порог брифа 100%, все отклонения перечисляются.
- **Задержка и эксплуатация** — p50/p95, количество замеров и доля вызовов LLM отдельно по маршрутам. Измерить обычный запуск и fallback. На малом наборе показать абсолютные значения и размер выборки. Стоимость одного поиска = (вызовы модели по фактическим тарифам за токены + инфраструктура за интервал) / число поисков за тот же интервал. Показать также на 1 000 поисков. Для локальной модели учитывать вычисления один раз. Индексацию учитывать отдельно. Неизвестный тариф обозначать как допущение с формулой.
- **Пример release verdict** — «HOLD на сборке X: A05 выдаёт совместимость для неподтверждённой версии. Владелец Senior. Повторить A05 на двух версиях после исправления». Для итогового отчёта использовать фактические значения. При неполном прогоне указать непроверенные сценарии.
